EquityAgent: Evidence-Grounded Agentic Equity Research¶

AAI 520: Natural Language Processing and Generative AI | Final project University of San Diego · Master of Science in Applied Artificial Intelligence · October 2026

Research team: Nicole Rowley (agent orchestration), Ashley Figueroa (NLP), and Pawan Bishwokarma (evaluation). Code and reproducibility: EquityAgent GitHub repository

Abstract¶

EquityAgent combines financial information retrieval, sentiment NLP and an iterative language-model research workflow. A LangGraph agent plans research for a stock ticker, routes tasks to earnings, market and news specialists that gather market, macroeconomic, filing and news evidence, verifies every figure in their findings against the raw tool data, synthesizes an equity brief, and revises it under a quality gate that checks rubric scores and recognized figures. A reflection step stores lessons that the next run's planner reads. The news component benchmarks LLM sentiment classification against keyword and supervised baselines. The agent component compares the brief with a no-tools baseline and with a single-pass brief written from the same evidence, and tests the effect of stored lessons. Experiments cover NVDA, JPM and XOM.

The agent's workflow. A ticker enters a LangGraph state graph and passes through eight stages: plan → route → specialists → verify → synthesize → evaluate ⇄ optimize → reflect. The planner reads stored lessons and writes a research plan; the router sends each step to an earnings, market or news specialist; the specialists call tools and write findings, interleaving tool use with reasoning in the manner of ReAct (Yao et al., 2023), with 10-K text retrieved by semantic search over filing sections (Lewis et al., 2020); a data verification specialist checks every figure in the findings against the raw tool output; the synthesizer writes a brief; an evaluator scores it and an optimizer revises it until a quality gate is met, following the generate–evaluate–refine loop of Self-Refine (Madaan et al., 2023); and a reflection step records lessons that the next run's planner reads, as in Reflexion (Shinn et al., 2023).

Models. The planner, router and news chain use gpt-6-luna; the specialists, synthesizer and optimizer use claude-sonnet-5; the evaluator uses gpt-6-sol, a different model family from the writer so that drafts are not graded by the model that wrote them. The verification specialist uses no model: it is rule-based, so its checks are reproducible.

Research questions and experimental design¶

  1. Financial NLP: How does an LLM sentiment classifier compare with keyword classification and TF–IDF logistic regression on a held-out set of labeled financial news sentences?
  2. Research agent: How do an evidence-informed research process and its revision loop compare with generation from a single prompt, with and without access to the same evidence?
  3. Evaluation controls: Do explicit evidence and accuracy thresholds, plus constrained numerical cross-checks, change which generated drafts are considered acceptable?

A2. Kaggle news EDA¶

The labeled dataset is Kaggle: Sentiment Analysis for Financial News (the Financial PhraseBank). The cell below downloads it once with the Kaggle API; add KAGGLE_API_TOKEN (newer Kaggle accounts) or KAGGLE_USERNAME and KAGGLE_KEY (older ones) to Colab Secrets, or drop all-data.csv into data/kaggle/ by hand.

The same sentences ship with the original release in data/kaggle/FinancialPhraseBank/ (Malo et al., 2014). Each sentence has 5 to 8 annotations, and the release groups sentences by how strongly the annotators agreed (100%, over 75%, over 66%, over 50%). The classifier diagnostics below use those groups to read the classifier's errors.

Cleaning. Rows are compared on a normalized key (case-folded, punctuation removed), which finds near-duplicates that an exact match misses (Jurafsky & Martin, 2026, Sections 2.4 and 2.6). A sentence that appears with two different labels has no single gold label, so it is dropped. The normalized key is used only for matching; the classifier sees the original text, because case carries sentiment signal (Section 2.6).

A3. Classifier evaluation: keyword baseline vs LLM¶

The LLM classifier is scored on the fixed 300-sentence held-out sample with a sentiment-only prompt. The live news chain uses a longer prompt that also asks for relevance, but the PhraseBank sentences have no target company, so that instruction would only add noise here. Because LLM output varies between runs (about 2 points of accuracy at n = 300), the score reported here is the mean of three runs. A4 adds the majority vote across the same three runs, which A5 uses as the primary metric.

A4. Classifier diagnostics: supervised baseline, few-shot prompts, agreement¶

Three checks on the zero-shot LLM classifier above:

  1. A supervised baseline. A pretrained model can be applied to a task by prompting it or by training on labeled data (Jurafsky & Martin, 2026, Section 9.4). TF-IDF with logistic regression, trained on the same train split, stands in for the second, so the LLM is compared with a model that learned from these labels and not only with keywords.
  2. Few-shot prompting. Two demonstrations per label are added to the prompt, drawn from the train split, as Brown et al. (2020, Section 2.4) draw conditioning examples from the training set and never from the test set. Demonstrations come from sentences every annotator agreed on, and K is fixed in advance rather than tuned on the test set. The sentiment definition in the prompt now restates the PhraseBank annotation guideline: judge only what the sentence states, from an investor's view of the stock price (Malo et al., 2014).
  3. Majority vote across runs. The three runs per prompt are combined by majority vote, the self-consistency idea of keeping the answer most samples agree on (Wang et al., 2023). It reuses the runs already made, so it adds no API calls.

Finally, accuracy is broken down by annotator agreement. If the model is far more accurate where every annotator agreed, many remaining "errors" are sentences that people also labeled differently.

B6b. Data verification specialist¶

Before any brief is written, a separate verification agent (src/agents/verifier.py) re-reads the raw tool output the specialists received and checks every financial figure in their findings. A figure is confirmed if it equals a raw value, or one computed from raw values (year-over-year change, margin, ratio as a percent, macro change), at the precision written; contradicted if the finding names a metric and fiscal year whose raw value differs; and not found otherwise, which flags it for attribution rather than proving it wrong.

The agent is rule-based, so its checks are reproducible and independent of the models that wrote the findings. Its corrections and flags travel with the findings to the synthesizer and the evaluator. News findings summarize article text, which the verifier does not hold, so they are not checked.

B7. Evaluator–Optimizer: generate, evaluate, and refine¶

The research agent synthesizes an initial brief, scores five criteria from 1 to 5 (completeness, evidence, accuracy, balance, and clarity), then uses specific evaluation feedback to revise the brief, following the generate–evaluate–refine loop of Self-Refine (Madaan et al., 2023). Claude Sonnet 5 writes and optimizes the drafts; GPT-6 Sol evaluates them. These are distinct model roles, rather than two independent scoring models.

The baseline acceptance policy requires an average of at least 4.0 after the minimum revision count. The enhanced quality policy additionally requires accuracy and evidence scores of at least 4/5, blocks acceptance on recognized numerical contradictions, records unresolved figures, and can select the highest scoring acceptable revision.

Acceptance rule Baseline Enhanced policy
Minimum average 4.0 4.0
Minimum accuracy No separate floor 4 / 5
Minimum evidence No separate floor 4 / 5
Minimum revision rounds 1 1
Maximum evaluated drafts 3 3
Contradictions found by limited numeric parser Not a separate gate Block acceptance
Final draft choice Last evaluated revision Best accepted revision

Figures are compared at the precision the brief writes them, so rounding ("$215.9B" for "$215,938M") is not a contradiction.

Unrecognized or unsupported claims are unverified, not proven correct. The parser covers only a narrow subset of financial prose; discrepancies require human review. Exhausting the evaluation budget does not constitute acceptance.

Part C. Evaluation and comparative analysis¶

Evaluation and Iteration¶

Part B showed one evaluate-and-revise loop in detail. This part measures the agent against simpler alternatives and tests what its quality controls change. Every comparison uses the same five-criterion rubric (completeness, evidence, accuracy, balance, clarity) scored by the same evaluator model, and every brief is graded against the same collected findings, so the comparisons differ only in what the writer was given and how the draft was produced.

The three experiments answer different questions and should not be combined into one causal claim:

  • C1 compares the agent with a no-tools baseline (the value of evidence plus workflow), with an evidence-matched baseline (the value of the workflow alone), and with itself with memory off (the effect of stored lessons). The memory comparison uses separate live runs, so model and data variation remain confounders.
  • C2 replays two acceptance policies on the same sequence of observed rubric scores, so it isolates the stopping rule.
  • C3 states the limitations.

Two independent checks accompany the rubric scores: the data verification specialist's count of figures confirmed against raw tool data (B6b), and the numeric audit's checks of recognized figures in the brief against the findings (B7). Both cover only the figures their parsers recognize.

C1. Report quality, numerical evidence, and memory¶

Four descriptive analyses are reported for NVDA, JPM and XOM:

  1. No-tools baseline versus research agent. For each ticker, a single prompt produces a brief with no findings, no plan and no revision. Both briefs are graded against the same collected findings. This measures the combined effect of research evidence and the agent workflow, not one component in isolation.
  2. Evidence-matched baseline versus research agent. A single-pass brief is written from the same findings the agent used, with no planning, revision or quality gate, and graded the same way. The gap to this baseline isolates what the evaluate-and-revise loop and the quality gate add beyond access to the evidence. This is the fairer of the two comparisons.
  3. Figure checks. Three counts are reported per ticker: figures in the specialists' findings that the verification specialist confirmed against raw tool data (figures_checked, figures_confirmed, figures_corrected); recognized figures in the kept brief that the numeric audit checked against the findings (numeric_checked, numeric_contradicted, numeric_unverified); and an exact-string count of figures in each brief that appear verbatim in no finding (unsupported_*). The last measure counts rounding, scaling and unit differences as unsupported, so it is a review aid, not a fact check.
  4. Memory on versus off. The same ticker is run with stored lessons hidden from the planner and then with them available. Plan length, lessons read and rubric scores are compared. Because these are separate live runs, LLM and data variation remain confounders.

Each agent run uses the reviewed evaluation policy (B7). The table below is written to Results/table1_integrated_live_run.csv and is the source for every figure quoted in the interpretation; no values are carried over from earlier runs.

Memory. This is a controlled decision-policy ablation using the exact same recorded NVDA drafts and LLM rubric scores. Both acceptance rules rely on the same GPT-6 Sol evaluator, while Claude Sonnet 5 is responsible for draft creation and revision. The enhanced policy adds separate evidence and accuracy thresholds, a contradiction gate for recognizable financial claims, and retention of an acceptable earlier draft when a subsequent revision is worse. Changes in acceptance logic alone should not be interpreted as validated gains in financial correctness or investment performance.

C3. Limitations and threats to validity¶

  • Data provenance and currency. Prices, key statistics, financial statements, news and macro series come from external APIs (Yahoo Finance, NewsAPI, FRED, SEC EDGAR) or local caches and reflect the run date. Figures should be cross-checked against the companies' published filings before any investment use.
  • Judge variability. Rubric scores come from a single LLM evaluator call per draft. The same code produced an agent-minus-matched-baseline gap of +0.1 in one run and +0.5 in the next, and the same-evidence baseline for JPM moved from 4.4 to 3.6 between runs. Differences of a few tenths between single runs are within this noise; only the gap to the no-tools baseline (about 2.5 points) is clearly outside it. Repeated evaluations and human ratings would be needed to estimate scoring reliability.
  • Single runs. Each comparison in C1 rests on one run per ticker and condition. The results are indicative, not statistically established.
  • Numeric coverage. The numeric audit recognizes only explicitly formatted claims (metric, optional fiscal year, value), so it checked between zero and four figures per brief. Figures are compared at the precision the brief writes them; an earlier exact-match version rejected rounded figures as contradictions, which is why two earlier runs kept lower-scoring drafts. A zero-contradiction audit is not a claim that all figures are correct.
  • Verification scope. The verification specialist checks figures in the findings against the raw tool data, not against the published filings, and computes only common derived values (growth, margins, ratios, macro changes). It could not match 21 of 196 figures in this run, mostly bank-specific JPM measures it does not compute; those are unmatched, not wrong. News findings, which summarize article text, are not checked at all.
  • Comparison scope. The no-tools baseline differs in available evidence, which the evidence-matched baseline removes; the policy replay shares observed scores; the memory comparison uses separate live runs. These answer different questions and should not be combined into one causal conclusion.
  • Memory. Stored lessons changed the plan in every run but never raised the memory-on score, because the lessons request evidence (peer multiples, segment revenue) that no current tool can retrieve. Learning is shown at the planning level only.
  • Benchmark leakage. The Financial PhraseBank is public and may have appeared in model pretraining. Classifier scores describe this benchmark and do not establish robustness on current market news, other languages or other companies.
  • Application scope. Generated briefs are research aids, not verified investment recommendations. Human review of sources remains necessary.

Discussion and conclusion¶

EquityAgent connects financial data retrieval, sentiment NLP, specialist research, data verification, structured synthesis, iterative evaluation and memory in one executable workflow. Part A tests the language component against baselines, Part B exposes every step of one research run, and Part C separates three kinds of evidence: rubric scores, source-grounding checks and acceptance decisions. The run answers the three questions posed at the start.

1. How does an LLM sentiment classifier compare with keyword and supervised baselines? On 300 held-out Financial PhraseBank sentences (Malo et al., 2014), the LLM reached a majority-vote macro-F1 of 0.863 (zero-shot) and 0.846 (few-shot), against 0.771 for TF-IDF logistic regression, the classical supervised approach (Jurafsky & Martin, 2026), and 0.575 for the keyword rule. The gap to both baselines is large and consistent across four runs; the gap between the two prompts is not. Neither few-shot demonstrations drawn from the training split (Brown et al., 2020) nor majority voting across runs (Wang et al., 2023) changed the ranking reliably, and accuracy falls to 42–47% for every classifier on sentences where the human annotators themselves disagreed, the agreement bands Malo et al. (2014) published with the data. The benchmark is public and may overlap with model pretraining, so these are benchmark scores, not a claim about unseen news.

2. How does the research agent compare with single-prompt generation, with and without the same evidence? Evidence does most of the work. Briefs written from the agent's findings, gathered by specialists that interleave reasoning with tool calls (Yao et al., 2023) and retrieve 10-K text by semantic search (Lewis et al., 2020), scored about 2.5 points above the no-tools baseline (4.0–4.6 against 1.6–2.0). The evaluate-and-revise loop, which follows the generate–evaluate–refine pattern of Self-Refine (Madaan et al., 2023), added +0.5 on average over the same-evidence baseline in this run and +0.1 in a second run of the same code, so its contribution is positive in direction but small and unstable in size. Its main value is auditability: every acceptance decision is recorded with its scores, critiques and numeric checks, and the verification specialist confirmed 175 of 196 finding figures against raw tool data before any brief was written.

3. Do explicit thresholds and numeric checks change which drafts are accepted? Not in this run: both policies revised the first NVDA draft and accepted the second, and the audit found no contradictions in any of the three C1 runs. They did in earlier runs, where exact figure matching rejected a higher-scoring draft over a rounded number; the gate therefore needs tolerant comparison to be useful. Memory, implemented as verbal lessons stored after each run in the manner of Reflexion (Shinn et al., 2023), changed what the agent planned (eight steps citing the stored lessons) but not how well it wrote (4.6 with memory against 4.8 without), because the lessons request evidence the current tools cannot retrieve.

A full NVDA run took under three minutes of wall time, with the three specialists running in parallel for about a third of it; the C1 comparison across three tickers, two baselines and the memory ablation is the bulk of the notebook's runtime and API cost.

Future work¶

  • Tools the lessons keep requesting: peer key statistics and segment revenue, so that the reflection loop (Shinn et al., 2023) can change the evidence, not only the plan.
  • Repeated evaluator calls, taking the median of three in the spirit of self-consistency (Wang et al., 2023), and several runs per condition, to separate real effects from judge noise.
  • Verification of news figures against the fetched article text, and bank-specific derived measures for financial-sector tickers.
  • A human spot check of brief figures against the published filings.

Reproducibility and implementation¶

Source code, data, tests and the notebook builder are maintained in the project repository, tagged v10.4 for this submission. The setup cell resets the working copy to the published main commit, prints that commit, and stops before any agent run if the code was loaded from anywhere else. All model results, tables and figures are calculated by the code cells during execution and saved under Results/; API responses and retrieval dates affect reproducibility. Secrets are loaded from Colab's credential store and never written into the notebook. The automated test suite (188 tests) runs offline with mocked models and tools; passing it does not establish that live research claims are correct.
